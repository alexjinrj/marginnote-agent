## 待解决

### 6. PDF 页面阅读遗漏 MarginNote 手写批注

**用户观察：** 直接在 MarginNote 的 PDF 页面上书写后，笔迹不会直接写回原 PDF，而是保存在 MarginNote 自己的数据中。因此，知道当前 PDF 文件与页码，再读取原文件，不一定能看到页面上新增的手写笔记。

**代码核对：** 当前 `read_pdf_page` 通过 MarginNote 获取本地文件位置和页索引，再用 PDFKit 渲染、提取原 PDF，并对渲染图片进行 OCR。这条路径尚未读取或叠加 MarginNote 独立保存的页面笔迹。返回页面图片或 OCR 成功，也不能证明已包含 MarginNote 中可见的手写批注。

**影响：** Agent 可能漏读手写、圈画等批注；针对“当前页面全部内容”进行问答时，会得到不完整的上下文。这与手写脑图卡片取图已修复是两个问题。

**后续方向：**

- 调查当前文档、当前物理页对应的 MarginNote 批注/笔迹数据及渲染接口，确认是否能取得带批注的页面图片。
- 优先复用 MarginNote 的页面渲染；若只能获取独立笔迹，再验证页码关联、坐标、裁剪、旋转和缩放后能否与原页面正确合成。
- 阅读结果需明确图片来源、是否包含 MarginNote 批注，以及批注读取失败或未支持的状态，不能把原 PDF 页面当作完整应用画面。

**验收：** 在原 PDF 无该笔迹的页面上添加手写内容；对照 MarginNote 画面与工具返回图片，确认 Agent 能读到新增笔迹。换页后只读取对应页批注，并验证重新打开文档后的持久化结果。

## 已修复或已实现

### 1. 当前 PDF 页码映射

已区分零基 `page_index`、物理页序 `page_number`、MarginNote 原生/映射页码和 PDF 页面标签，避免混用显示页码与文件页索引。含封面、罗马数字及自定义起始页码的实机对照仍待验收，不再将全部页码定位功能列为未实现。

### 2. 手写卡片图片读取与识别

`read_card` 一次返回文字、评论、关系与可用图片，检测手写证据，并支持关联视觉评论、sketch 和媒体分页。当前手写卡片已通过真实 MCP 返回 JPEG，打开后可读到命题逻辑推导。

Host/MCP 0.9.1 将私有缓存读取放到后台 Host，修复 Claudian/Codex 客户端无法访问缓存时仅收到笔画信息的问题。当时的 Host 由用户手动启动；0.9.2 起该进程由 Homebrew supervisor 管理。限制客户端缓存读取权限的测试已成功返回真实图片；实际 Claudian 会话仍需重启 Host、重连 MCP 后复测。无需重新安装 0.9.0 Add-on。

手写转写由客户端视觉模型完成，桥接层不自行生成转写文本。模糊字符、公式准确率及缓存缺失时的降级仍需核对，不再笼统记录为“无法读取手写”。PDF 独立笔迹层另见问题 6。

**2026-10-13 更新：新增桥接层 Apple Vision OCR。** 桥接层在返回笔记卡片图片媒体时，自动对 >1KB 的图片调用本地 `image-ocr` 二进制（Objective-C，Vision Framework），返回 `ocr_text` 和 `ocr_engine` 字段。OCR 识别出的清晰文字与原始图片一起返回给 Claude：文字部分由 OCR 覆盖，数学公式等复杂符号由 Claude 视觉模型判断。此为分层策略，实机复测中。

**2026-10-27 修复：** 已修正 OCR 原生编译错误及构建脚本吞错；手动 Host 与服务统一辅助程序路径，并重新生成与源码一致的发布插件包。macOS 原生 OCR 已正确识别生成测试图中的文字，新增三项回归测试，全部 72 项测试通过；实际手写样本及 Claudian 会话仍待复测。

### 3. 批量读取卡片树及总数

`read_card_tree` 可按学习集或根卡片返回快照分页、准确 `total_count`、父子关系和视觉内容提示，不再需要逐卡调用并遍历子节点。读取完整范围时仍需跟随分页；图片及超长卡片内容按需用 `read_card` 补读。大库总数、性能与续读边界保留为验收项。

### 5. 聊天知识框架写入脑图

`create_cards` 支持一次最多 30 张普通卡片的层级创建、正文及写后核对；已有卡片可追加评论、将摘录转为标题，并通过预览/应用工具重组。Agent 整理对话中的知识框架，桥接层负责写入；重复内容由调用方在写入前处理。
